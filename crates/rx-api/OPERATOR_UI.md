# Serving the S operator application directly over terminal HTTPS

P serves pinned bytes of the UI built by S. UI sources/builds and `/opt/rx/operator` artifacts belong to S; no ROS, Node, or application-build dependency is added to P. The product retains its two existing images.

Optional `operator_ui` in P startup accepts an absolute `directory` path and `manifest: {path, sha256}`. The manifest path must be exactly `directory/operator-bundle.json`. Installation tools extract the bundle from a digest-pinned S image, publish it by version, and mount it read-only in P. It must not overlap P data/runtime/package import paths. Omitting configuration preserves API-only behavior; verification failure for a configured bundle fails startup.

The manifest schema is `rx.operator-ui-bundle.v1`, and `api_schema` is `rx.operator-api.v1`. `files` is sorted by ascending path; each entry contains `path`, SHA-256 `sha256`, and Counter string `size_bytes`. The manifest itself is excluded. Only `index.html` and js/css/woff2/woff/png/jpg/jpeg/svg/ico/webp/json files under `assets/` are allowed. P determines MIME types from a fixed table.

Limits are 1,024 files, 8 MiB per file, and 64 MiB total. 0-byte assets are rejected, and the manifest is limited to 1 MiB. File paths follow shared PackagePath rules: 240 ASCII characters, 100 per component, forbidden reserved filenames/trailing dots, and at most 16 components. Duplicate/out-of-order paths, traversal, symlinks, unlisted files, special files, and size/hash mismatches are rejected. Root and ancestors must also be normalized absolute paths without symlinks.

Manifest/asset bytes are acquired under the root through existing `rx-package::directory::read_relative_file`. It reuses intermediate-directory/leaf nofollow, Unix NONBLOCK, regular-file checks on actual opened descriptors, and read limits. An inventory check is not authority for a later open; replacing a file with a FIFO/link before acquisition does not make it readable as a regular file. Verified bytes are retained in memory, so requests do not reopen disk files. Runtime bundle changes are unsupported and are revalidated at the next startup. This hardening covers acquisition beneath a trusted deployment root. Read-only deployment roots and a trusted host OS remain assumptions; it does not claim protection against path/mount replacement by an entirely malicious host.

Overlap checks between UI and data/runtime/import resolve existing ancestors to their actual paths, then append directory suffixes not yet created. With UI configuration enabled, `..` in compared paths is explicitly rejected, as are dangling links and non-directory ancestors. Existing aliases such as `/var` are allowed when their actual locations are separate. The comparison does not create directories.

`TerminalHttps::new_with_operator_ui` combines the static router and existing API router. Earlier constructors remain wrappers without a bundle. Only the actual TLS-validated client leaf creates TerminalPeer. Static GET/HEAD are served under the same mTLS and Host/origin boundary, but create no human session or business authority. Existing `/api` retains unregistered-terminal login rejection and registered terminal/user session/role checks. Cookies retain `Path=/api; Secure; HttpOnly; SameSite=Strict`. Proxy certificate headers are not trusted.

Static routes are only `/`, `/index.html`, and exact asset paths in the manifest. There is no SPA fallback or arbitrary directory serving. Missing APIs/assets/deep links return the existing JSON 404, and POST to static paths returns 405. APIs retain existing CSP; UI script/style/font/connect/img are restricted to self. Inline scripts/styles, eval, and external CDNs are forbidden. Responses use no-store/nosniff; HEAD returns the same Content-Length without a body.

Validation covers owned-byte preservation, manifest/asset tampering, size/path counterexamples, actual combined mTLS static/API serving, terminal-cookie replay/revocation, and a fresh startup without operation. Integration of the actual S production bundle with a browser is validated separately. Accessing the UI does not imply qualification or Run start.

Browser/image test inputs are exported by the existing ignored `export_container_fixture` in `rx-platformd` composition. `RX_PLATFORM_IMAGE_FIXTURE` specifies a new output directory; `RX_PLATFORM_IMAGE_PORT` specifies the external HTTPS port. Optional `RX_PLATFORM_OPERATOR_BUNDLE` supplies an actual S bundle path: the source is verified, and startup references a read-only `/operator` mount. Existing `/config` and `/data` mounts are used. `terminal.pem/key` identify a catalog-registered test terminal; `browser-fixture.json` contains test login information. Existing `probe.pem/key` identify a service peer and must not be repurposed as a human terminal.
