# Revalidation entry point for an already installed process configuration

If initial bootstrap contains a compiled process but no applied Change record for that configuration, `ProcessChange.Propose` with `mode: "REVALIDATE_CURRENT"` explicitly creates a root for the verified and approved current configuration. The existing mode when input is omitted is `REPLACE`, and existing JSON omits mode. Existing REPLACE plan digest computation is preserved; only REVALIDATE_CURRENT binds to a separate mode digest.

REPLACE continues to reject a verified target identical to the current configuration. REVALIDATE_CURRENT requires an existing current compiled process and an entire verified target exactly identical to the current configuration. If an APPLIED_UNQUALIFIED or QUALIFIED_ACTIVE application root includes that same current configuration, the request is rejected as Busy and the existing root is reused. This check runs at proposal and commit, and during subsequent currency checks for stage/preparation/application. Retrieval of existing results under the same request key is preserved.

The API Change's `mode: "REVALIDATE_CURRENT"` and identical before/after artifacts indicate that no configuration replacement occurred. Proposal, independent impact review, stage, existing fence confirmation and Host metadata ACK are all required before APPLIED_UNQUALIFIED. Application creates neither fresh qualification nor operating authorization, and does not directly clear blocks. Existing blocks requiring preparation for Host binding changes based on device provenance are also preserved.

The existing source worker uses the same Prepared verification path, so there is no separate bypass worker or bootstrap-only approval path. Dedicated tests cover preservation of existing wire/plan behavior, exact compiled targets, requirements for independent review/fences/Host ACKs, unqualified application, reuse of existing roots under concurrent proposals, errors before/after commit and same-request retrieval. Physical equipment verification and qualification issuance are outside this scope.
