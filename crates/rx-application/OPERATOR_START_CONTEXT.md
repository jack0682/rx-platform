# Start candidates and start-attempt reads

`GET /api/v1/run/start-context?cell=...&run=...&purpose=PRODUCTION&budget_limit=2` checks the current Operator and cell access, then returns current revision/configuration/envelope/maximum quantity/Run and an actual StartRun candidate in the same transaction. `budget_limit` is a Counter string; purpose determines budget unit as PRODUCTION/PART_ATTEMPT or SETUP/OPERATION_COUNT. If the current Run already has a budget, the existing value is shown and different candidates return rejection reasons.

`can_request` is candidate evaluation at `checked_at`, not a permit or completed start. A valid Operator session without a registered terminal can receive `blocking_reason=FORBIDDEN`, but business payloads for inaccessible cells or retired terminals are not returned. Remaining executability follows current qualification/conditions/Host/Executor sessions and actual StartRun checks. Unclear internal state is not replaced with arbitrary normal values.

Engine's `operator_start::validate_candidate` is a shared read-only check. Existing StartRun preserves the ordering of current user/terminal authority checks and original-key recovery, then invokes this check. Only subsequent mutation records budget/attempt/Arm outbox. Context reads create no journal entries/budget/attempt/qualification. There is no separate PrepareStart authority/token. The UI fixes the exact returned candidate in a confirmation dialog, while actual dispatch lets existing StartRun recheck CAS and conditions.

`GET /api/v1/run/start-attempt?cell=...&run=...&id=...` checks existing cell read access and exact cell/run/attempt correlations and returns the current Run and stored StartAttempt. `deadline_status` is WITHIN_DEADLINE/ELAPSED/CLOCK_CHANGED, separate from stored status. Reading ELAPSED does not change ARMING to REJECTED or undo STARTED. Only STARTED/EXECUTING recorded by P after all actual Host ACKs establishes a committed start.

The subsequent resident cell executor service must open and maintain an actual session while idle without a Run. The intended path connects it to ARMING/EXECUTING Runs through assignment reads after StartRun, without requiring advance assignment of a specific Run or Executor credentials in the browser. The current implementation covers read APIs and their checks; actual resident-service integration is follow-up work. Host producer reconnection, full recovery and explicit reconciliation of expired attempts are separate implementation scope. Deadline expiry alone does not currently trigger automatic retries of a new start.

The written tests cover separation of read-only candidates and explicit mutation, actual acknowledgments from two Hosts, budget/envelope/unit tampering/stale revisions, Operators without terminals and cell/installation access, same-attempt recovery after lost responses, non-mutating deadline reads, direct mTLS HTTP reads and terminal retirement. SIMULATION fixtures test operating-software boundaries and do not commission the first physical cell.
