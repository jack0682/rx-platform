# Evidence producer session replacement caused by P restart

`OpenEvidenceProducer` returns the existing session when reconnecting in the current P runtime with the same Host boot/evidence journal/authentication binding. When only P restarts and session.runtime_boot changes, a new evidence session is required.

In this case, it checks that the previous producer's principal/Host boot/evidence journal/authentication binding and the previous active service session's principal/shared clock/validity remain the same, with only runtime_boot changed. It then checks the exact latched RuntimeRestart block and immutable origin created by the current P runtime when revoking the previous session's runtime_boot in **all previously registered cells** of that Host. The origin's installation/store generation/cell/block/before-and-after boundary must be valid; the current configuration digest and complete scope-key coverage must also match.

If all this evidence exists, no new DeviceRestart is added. Existing RuntimeRestart, AuthorityRevoked and other blocks, cell revision/epoch/scopes, qualification, Run, mandate, permit, work, HostRegistration and grant remain unchanged. Only existing authentication processing occurs: creating a new producer session, deactivating the previous session and clearing the cell negotiation map. A new Cell.Open and evidence-prefix verification are still required.

`OpenEvidenceProducer` input does not contain a source generation. This branch does not evaluate source continuity or classify incidents where only the source changed. Actual source-change decisions, fact invalidation and DeviceRestart fencing remain the responsibility of the existing observation path. Source DeviceRestart blocks, bad facts, original evidence and source-generation-loss records already stored by that path, and HostRegistration pinned to a historical source, remain intact after P runtime evidence reconnection. This session decision does not approve source changes or operating rebinds.

A normal P stop stores AuthorityRevoked and lifecycle records but does not change evidence service Session.active. Therefore, a normal stop → P restart with the same DB/clock also falls under this narrow decision, and restrictions from the normal stop are not removed. If the previous session is already inactive/expired, Host/auth/journal/clock has changed, or origin/current boot/configuration/complete cell-and-scope coverage is missing, the existing DeviceRestart revocation path applies. A corrupted origin or one belonging to another installation/cell causes an integrity error and transaction rollback.

If the old producer session predates the runtime immediately preceding the current origin, no origin chain is inferred. Conversely, if evidence renegotiation completes between each P restart, the new immediately preceding session can be compared with the current origin each time. Even then, the old session in the operating HostRegistration is not automatically rebound.

This change narrowly distinguishes incident causes. It adds no operating HostRegistration rebind, grant acquire/renew, qualification restoration/activation, Arm, StartRun or native submission. It also changes no base/cell normative definitions, SDK or public wire format.

Dedicated transaction test sources cover actual producer session replacement after normal/abnormal P exit, byte-equivalent preservation of all registered cells and authority records/outbox, Host/journal/auth/clock/origin/scope counterexamples, pre-commit failures/lost commit responses, consecutive P restarts, and preservation of facts/evidence/registrations/blocks from existing source-generation revocation. Idle publisher reconnection between actual P/H processes is a separate integration-test scope.
