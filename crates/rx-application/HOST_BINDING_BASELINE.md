# Immutable evidence for a normal Host binding

`PrepareHostLink.provenance` and the same field in a stored Plan are optional. Only an internal HostClient that has completed actual pinned-transport and Host configuration/read validation supplies `Some(BootstrapProvenance)`. Existing legacy `None` remains readable and is omitted during serialization. Reading a legacy plan or replaying its commit does not backfill evidence. Conversely, a request to downgrade a plan that already has provenance to `None` is rejected even after expiry.

TransportPin fixes the public HTTPS origin/server name, SHA-256 of the CA/client-chain PEM bytes used, actual Host/P client leaf DER SHA-256, release and actual base/cell/HostRead/HostConfig wire hashes. URIs cannot contain user information, query, fragment or arbitrary paths. Private keys, Runtime instance and lease TTL are excluded from the pin. TransportPin digest is the canonical domain digest of these public fields.

BootstrapProvenance preserves the actual Host configuration Observation and its P read window, plus original HostRead data that exactly matches the existing Prepare.snapshot canonically. The configuration read must span at most 100ms on the same shared clock and end before HostRead. Host configuration and HostRead are compared for host/cell/boot/delivery journal/definition/envelope/environment/epoch/scopes/blocks. The existing bootstrap rule that Host epoch/scopes are no greater than P's is preserved. The subsequent original Fence ACK establishes the exact P bound cut. An initial applied context of None is a valid observation and does not mean application is complete.

In the **same transaction** that a new normal CommitHostLink stores the actual registration, fence receipt, BoundReceipt and bound Plan, it creates a plan-ID-keyed `HostBindingBaseline` and original-data sidecar once, each at revision1. Neither exists after commit rollback; exact replay after a lost response leaves only the original values. A different commit body, changed transport/configuration identity on a reused plan, or an already existing baseline/source row is a conflict. Replay of an already Bound plan does not execute baseline creation again.

The baseline contains installation/store/runtime, producer authentication/session, bidirectional sessions, Host boot/both journals/source map, transport and digest, original P configuration digest, Host binding digest and applied context, original bound epoch/scopes and observation references. The original-data sidecar preserves the initial bound Plan, provenance HostRead/configuration/source originals, installation/producer/P CellConfiguration at that time and immutable BoundReceipt. The baseline also fixes an ArtifactRef for the sidecar's **entire canonical original content**, so producer.cells and installation.clock_id absent from separate projections are included in hash/size validation. The sidecar does not contain the baseline, avoiding reference cycles. Baseline reads recheck original hash/size/schema/correlations and original plan/registration digest, and compare the stored BoundReceipt. Missing/tampered originals or incorrect references are not replaced with legacy None or current evidence.

Even without a primary baseline, a remaining source or a known bound Plan with provenance Some is an integrity error. A contradiction where only BoundReceipt remains without a Plan is not treated as initial absence either. Only actual legacy None, plans not yet bound and plan IDs with no history retain None on read. Missing immutable records are not recreated during reads or replay.

`Engine::host_binding_baseline(plan)` is an internal historical read. It returns no current qualification/grant/Arm/start authority. Original plan/registration digests identify historical objects and are not compared with renewed current Plan.valid_until or complete HostRegistration/P configuration after normal changes. A separate `stable_identity()` projects only installation/store and Host/cell/Host boot/journals/source map/transport digest. This projection does not automatically restore Runtime/session/lease/current epoch/configuration.

This stage does not implement RecoveryBinding, explicit rebind HTTP/CLI or qualification/Arm recovery. It does not relax existing authority/generation/lease checks in prepare/commit/renew or change base/cell normative files, SDK or public wire.

Dedicated test sources cover initial None applied context, pre-Fence H cut lower than P, original/reference validation, commit rollback/lost response/replay, legacy no-backfill, pin changes/None downgrade, configuration/window counterexamples and historical reads after renewal/subsequent epoch changes. Actual pinned transport/optional configuration reads and product integration are validated in separate HostClient tests.
